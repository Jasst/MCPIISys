# Память и идентичность (v9)

## Три слоя, три правила

| Слой | Что здесь | Кто пишет | Как читается |
|---|---|---|---|
| **Память** (факты, эпизоды, цели) | факты о пользователе и мире, события | модель через `remember`, автоматически из диалога | `recall` и поиск по запросу |
| **Личная идентичность** (ТЕКУЩЕЕ_Я, private) | самоформулировки модели из её диалогов | модель через `identity_propose` → `identity_commit` | блок «ТЕКУЩЕЕ_Я» в контексте пользователя |
| **Общее ядро** (shared) | одинаковая для всех основа личности | только администратор командами «ядро: …», «да», «откатить ядро» | блок «ОБЩЕЕ ЯДРО», только чтение |

Правило: **идентичность — то, что модель вывела о себе из диалога. Факты о мире и пользователе — память.**

## Личная идентичность: жизненный цикл звена

1. Модель замечает что-то о себе в диалоге.
2. `identity_propose(content, kind, evidence)`: текст от первого лица (30–600 символов), тип (`value | style | self_observation | commitment | open_question`) и **дословная цитата** из диалога.
   Ворота (`GCN/identity_gate.py`) отклоняют шум (код, JSON, служебные маркеры, id), факты (даты, адреса, телефоны), формулировки без опоры в диалоге и дубликаты головы.
3. Кандидат попадает в карантин (`GCN/identity_quarantine.py`). В цепочку он попадает, только когда подтверждён в `IDENTITY_MIN_DAYS` (по умолчанию 2) разных днях.
4. `identity_commit(candidate_id)` пишет звено в **личную** цепочку. Ворота проверяются повторно.

Личная цепочка никогда не видна другим пользователям и никогда не попадает в общее ядро автоматически.

## Общее ядро: только по решению администратора

Администратор — пользователь из `MCP_ADMIN_USERS`. Команды в чате:

- **«ядро: <текст>»** — предлагает формулировку, ваш текст, показывается **точно**.
- **«запиши в ядро»**, **«обнови ядро»** (без текста) — модель формулирует 1–2 предложения из последнего разговора и показывает их вам. Вы читаете и решаете. Модель ничего не записывает сама.
- Любой вариант проверяется (длина 30–400, самоописание, без инструкций). Если черновик модели не проходит проверку, он не предлагается.
- **«да»** — применяет предложение. Работает **только** пока есть ожидающее предложение, которое администратор уже видит, и только в течение 10 минут. Без предложения «да» — обычное сообщение.
- **«нет»** — отменяет предложение.
- **«откатить ядро»** — помечает последнее применённое звено недействительным с причиной. Ничего не удаляется.

Ограничения: не чаще одного изменения в `CORE_MIN_INTERVAL_HOURS` (по умолчанию 24 часа); формулировка, совпадающая с текущим ядром, не применяется; журнал решений — в `ai_memory_v3/core_admin.json`.

Вопрос цепочки в общем ядре задаёт только администратор. Система его не генерирует.

## Что видит модель

Два блока в контексте, если есть данные:
1. **ОБЩЕЕ ЯДРО** — одинаково для всех пользователей, только чтение, не больше 400 символов.
2. **ТЕКУЩЕЕ_Я** — личная цепочка этого пользователя, не больше 600 символов.

Модель не может менять ядро и не видит личных цепочек других пользователей.

## Что не делаем, и почему

- **Автоматического развития общего ядра из опыта пользователей нет.** Такой механизм сам выбирал бы формулировки и мог бы вносить чужие личные мнения в общую личность. Если нужно учитывать опыт, безопаснее сформировать для администратора отчёт: тематические группы личных формулировок без текстов и без пользователей, а текст ядра администратор пишет сам.
- **Пула обобщений и уведомлений о предложениях нет.**

## Настройки

- `IDENTITY_MIN_DAYS` (по умолчанию 2) — сколько разных дней нужно для личной записи.
- `MCP_ADMIN_USERS` — администраторы (через запятую).
- `CORE_MIN_INTERVAL_HOURS` (по умолчанию 24) — минимальный интервал между изменениями ядра.

## Какие инструменты в каком слое

Правило одно: **ни один инструмент не пишет в общее ядро напрямую.** Ядро меняется только через `core_command` (MCP, только администратор) или команды в чате (тот же модуль `core_admin`).

| Слой | Чат (модель) | MCP (внешний ИИ) |
|---|---|---|
| **Память** (факты о пользователе и мире) | `recall`, `remember`, `memory_search`, `memory_update`, `memory_forget`, `memory_explain` | `recall`, `remember`, `forget`, `update_fact` |
| **Личность** (ТЕКУЩЕЕ_Я, только о себе) | `identity_propose` → `identity_commit`, `get_identity_chain`, `search_identity_chain`, `invalidate_identity` (только личное звено) | `get_identity_chain`, `search_identity_chain` (только чтение; запись — в чате) |
| **Общее ядро** (одинаково для всех) | только чтение (блок контекста) | `core_command` (только администратор) |
| **Утилиты** | `web_search`, `generate_image`, `inspect_image`, `read_code`, `analyze_error`, `fetch_github_file`, `add_goal`, `ask_user` | `web_search`, `generate_image`, `fetch_github_file`, `analyze_error`, `get_goals`, `add_goal`, `session_start` |

Инструменты разработки (`semantic_search`, `graph_explore`, `get_memory_stats`, `get_autonomy_status`, `research_topic`, `remember_batch`, `remember_with_handshake`, `read_code_file`, `search_in_code`, `execute_command` и др.) в MCP скрыты по умолчанию. Включить: `MCP_DEV_TOOLS=1`.

Удалено как мёртвое или дублирующее: `contribute_to_identity` и `merge_identity_branches` (и в чате, и в MCP), `invalidate_identity` в MCP (откат ядра — `core_command`), `list_tools` остаётся в чате; дубли `read_code_file` и `search_in_code` скрыты в чате (есть `read_code` и `search_code`).
