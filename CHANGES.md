# Улучшения памяти и нейросетевой части

Изменения основаны на чтении кода. Полного прогона с реальными моделями (sentence-transformers, faiss, LM Studio) не делалось: в среде их нет. Проверено так:
- `tests/test_improvements.py` — 20 юнит-тестов чистой логики (пластичность, онлайн-обучение, калибровка). Запуск: `python -m unittest tests.test_improvements`.
- `tests/smoke_memory_stubs.py` — реальные методы `CognitiveMemory` (с заглушками faiss/sentence_transformers): асимметрия STDP, метапластичность, масштабирование хабов, обучение весов по `apply_feedback` и их восстановление после перезапуска.
- `tests/identity_critic_check.py` — критик идентичности на методах из `routes/ai_assistant.py` (с фейковым эмбеддером и цепочкой ТЕКУЩЕЕ_Я).

## Что сделано

1. **STDP с реальным порядком событий** (`GCN/memory_graph.py`, `_hebbian_update`). dt = t_post − t_pre по времени событий обоих узлов, направления учитываются отдельно. Раньше dt считался от last_activation синапса, и окно почти никогда не срабатывало.
2. **Реальные времена реплик**. `Episode` хранит `user_ts`/`assistant_ts`; `user_ts` фиксируется в `_prepare_messages`, `assistant_ts` — при сохранении. Если времени нет (старые данные), используется прежнее смещение.
3. **Метапластичность** (`GCN/plasticity.py`). Пластичность = max(floor, initial / (1 + k·n)) по числу подтверждений. Раньше порог стабилизации был недостижим для шагов обычной ветки.
4. **Синаптическое масштабирование** (`_scale_synapses`). Входящая и исходящая сила узла ограничены `SYNAPSE_NODE_STRENGTH_CAP`, вызывается в `deep_consolidation`.
5. **Онлайн-обучение весов поиска по обратной связи** (`GCN/learned_rerank.py`). Признаки каждого результата запоминаются при поиске (`_record_retrieval_features`). `apply_feedback` обновляет веса логистической регрессией с L2 к априорным значениям. Веса сохраняются в `<cognitive_memory>/rerank.json` и загружаются при перезапуске. Ручная корректировка весов рефлексией LLM продолжает работать, но перезаписывается при следующем обучении.
6. **Консолидация по числу эпизодов** (`add_episode` → `_run_triggered_consolidation`). Помимо таймера, запускается после `DEEP_CONSOLIDATION_EPISODE_TRIGGER` новых эпизодов.
7. **Критик идентичности** (`routes/ai_assistant.py`). Сравнивает ответ с текущей версией ТЕКУЩЕЕ_Я (последний валидный голос цепочки), а не с топологическим ядром. Один эмбеддинг на текст вместо двух.
8. **Калибровка порогов** (`GCN/calibration.py`, `tools/calibrate_thresholds.py`). Пороги выбираются максимизацией F1 по размеченным парам. Результат пишется в `GCN/calibration.json` и подхватывается `config_ai.py`.
9. **Размерность эмбеддингов**. `EMBEDDING_DIM` приведён к 1024 (multilingual-e5-large). Раньше стояло 384 от MiniLM, а в `GCN.py` — fallback 128.
10. **Бюджет памяти в промпте** (`MEMORY_CONTEXT_MAX_CHARS`). Факты добавляются по убыванию релевантности до лимита символов.
11. **Единая рабочая память**. Показанные модели факты добавляются в `hierarchy`, которая задаёт стартовый узел графового поиска.

## Что не сделано (и почему)

- **Структурированный вывод LLM (JSON schema)** для извлечения фактов, противоречий и ревью. Нужно менять все точки вызова в `llm_client` и парсеры; это отдельная итерация.
- **Предиктор переходов на эмбеддингах (MLP/GRU)** вместо текстовых ключей. Нужны torch и обучающие данные из реальных диалогов.
- **Разделение времени события и времени записи**. Требует поля в схеме GCN-объектов и миграции данных.
- **NLI-модель для противоречий** вместо LLM на каждую пару. Нужна отдельная модель и калибровка.
- **Структурированная идентичность и хеш-цепочка**. Схема ТЕКУЩЕЕ_Я меняется, и это решение должны принимать вы.
- **Улучшения memory viewer** (толщина рёбер по весу, подсветка активации, дифф Hebbian-обновлений, очередь противоречий). Это работа в `static/memory_viewer.html` и `memory_viewer_core.py`; запланирована отдельно.
- **Значения порогов по умолчанию** (`IDENTITY_HANDSHAKE_THRESHOLD = 0.25`, `IDENTITY_CONSISTENCY_THRESHOLD = 0.35`) не менял: нужны реальные размеченные пары для калибровки.

## Как калибровать пороги

Файл pairs.jsonl, одна строка на пример:
`{"kind": "handshake", "a": "новая версия", "b": "предыдущая версия", "same": true}`
`{"kind": "consistency", "a": "ответ ассистента", "b": "текст ТЕКУЩЕЕ_Я", "same": false}`

Запуск: `python tools/calibrate_thresholds.py pairs.jsonl`. Для калибровки нужно хотя бы несколько десятков примеров каждого вида, иначе порог будет случайным.

## Новые переменные окружения

SYNAPSE_NODE_STRENGTH_CAP (3.0), PLASTICITY_FLOOR (0.05), PLASTICITY_STABILIZE_K (0.1), DEEP_CONSOLIDATION_EPISODE_TRIGGER (20), RERANK_LEARNING_RATE (0.01), RERANK_L2 (0.05), RETRIEVAL_FEATURE_CACHE_SIZE (500), MEMORY_CONTEXT_MAX_CHARS (3500).


# Раунд 4: схемы LLM, время события, NLI, предиктор переходов

Проверено: `tests/test_round4.py` (17 тестов, включая сверку градиента с конечными разностями и гейт на случайных данных), `tests/test_llm_response_format.py` (настоящий HTTP-сервер: отказ по схеме -> повтор без неё), `tests/contradiction_flow_check.py` (порядок NLI и LLM, отказ по схеме), `tests/transition_integration_check.py` (обучение и использование предиктора в `CognitiveMemory`).

1. **JSON schema для LLM.** `GCN/json_schema.py` содержит схемы вердикта противоречий и списка фактов, плюс минимальный валидатор. `llm_client.call_llm` / `call_llm_raw` передают `response_format`; при 400 повторяют запрос без схемы. Схема включена в верификатор противоречий и в экстрактор фактов из поиска. Не переведены: ревью viewer, рефлексия весов, вопросы для поиска (там свободный текст).
2. **Предиктор переходов на эмбеддингах.** `GCN/transition_model.py`: двухслойная сеть на numpy с ручным градиентом (torch не нужен). Обучается на парах соседних реплик в `deep_consolidation`. Принимается гейтом: на отложенной выборке hit@k должен превышать базовый уровень «популярность концептов» на margin. Иначе не используется. Файл `transition.npz` в каталоге пользователя. Используется в `predict_next`, если принят.
3. **Время события.** `GCN/temporal.py` нормализует даты из экстрактора. Дата сохраняется в `object["event_time"]` при записи, попадает в результаты поиска и показывается в контексте как «событие ...». Свежесть поиска по-прежнему считается по `last_accessed`/`created`: событие и запись разделены, но поиск по «когда» не добавлен.
4. **NLI для противоречий.** `GCN/nli.py`. Если задана `NLI_MODEL`, NLI решает до LLM: entailment или neutral с вероятностью >= `NLI_DECISION_THRESHOLD` -> ложное противоречие без вызова LLM. По умолчанию выключено (`NLI_MODEL` пуст). Порядок меток и порог не откалиброваны.

## Что не проверено

- Реальная NLI-модель (Hugging Face не в списке разрешённых доменов песочницы), порядок меток и порог.
- Реальная LM Studio с `response_format`: проверено на тестовом сервере.
- Полный путь `event_time` через `router.retrieve` и повторный поиск: проверены отдельные части.
- Предиктор на реальных диалогах: проверен на синтетической цепочке тем. Стоимость обучения: до 1000 пар эмбеддингов на каждую консолидацию.

## Новые переменные окружения

NLI_MODEL (пусто), NLI_LABELS (contradiction,entailment,neutral), NLI_DECISION_THRESHOLD (0.85), TRANSITION_TOP_K (5).
